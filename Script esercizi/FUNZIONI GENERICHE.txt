--------------- WHERE CLAUSE ----------------------
Per usare where, viene utilizzata come condizione di ricercar (quindi per mettere delle condizioni ad esempio sulle proprietà)

MATCH (a:Person) WHERE a.name STARTS WITH 'A' RETURN a

--------------- WEIGHTED CENTRALITY ---------------
MATCH (c:Character)-[r:INTERACTS]-()
RETURN c.name AS character, SUM(r.weight) AS weightedDegree
ORDER BY weightedDegree DESC

// WEIGHT DI UNO SHORTEST PATH	
MATCH p = SHORTEST 1(catelyn:Character {name: "Catelyn"})-[: INTERACTS*]-(drogo:Character {name: "Drogo"})
RETURN [n in nodes(p) | n.name] AS character, reduce(s = 0, rel in relationships(p) | s + rel.weight) AS total_weight

---------------- DEGREE CENTRALITY ----------------
MATCH (c:Character)
RETURN c.name AS character, COUNT { (c)-[:INTERACTS]-() } AS degree
ORDER BY degree DESC

----------------- PIVOTAL NODES E NODI IMPORTANTI --------------------	
MATCH (a:Character), (b:Character) WHERE id(a) > id(b)
MATCH p=allShortestPaths((a)-[:INTERACTS*]-(b)) WITH collect(p) AS paths, a, b
MATCH (c:Character) WHERE all(x IN paths WHERE c IN nodes(x)) AND NOT c IN [a,b]
RETURN a.name, b.name, c.name AS PivotalNode SKIP 490 LIMIT 10

Si trovano tutti gli shortest path e i nodi pivot sono i più important in queste relazioni
Lo skip è per ridurre il numero di ricerche. Altrimenti troverebbe (nei grafi troppo grandi) troppi risultati.

---------------- DIAMETRO DELLA RETE -----------------------------------	
MATCH (a:Character), (b:Character) WHERE id(a) > id(b)
MATCH p=shortestPath((a)-[:INTERACTS*]-(b))
RETURN length(p) AS len
ORDER BY len DESC LIMIT 10
